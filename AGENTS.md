# Loophole — notes for coding agents

Loophole is a macOS menu bar app that switches a [Pi-hole](https://pi-hole.net)'s ad blocking on and off, including timed pauses. It is a small, dependency-free Swift package. This file records how it is put together, why some things are the way they are, and what has and has not been verified.

## What the app does

- A status item in the menu bar opens a panel with:
  - a header (status badge, "Pi-hole", state line, on/off switch),
  - **Pause Blocking** pills (30 sec, 5 min, 15 min, 1 hour, and "Other" for a custom number of minutes or hours, up to a day),
  - a **Status** card (blocking state, queries per minute, load averages, memory),
  - four **Last 24 Hours** tiles in the Pi-hole admin page's colours (Total Queries, Queries Blocked, Percentage Blocked, Domains on Lists),
  - footer rows: Open Pi-hole Admin, Settings…, Quit.
- During a timed pause the time remaining is shown as plain text next to the menu bar icon (optional).
- Settings: Pi-hole address and password, self-signed certificate toggle, two global keyboard shortcuts (pause for N minutes, resume), show-countdown toggle, open at login.
- Pi-hole runs pause timers itself; the app only asks for them and displays the result.

Requires macOS 15+ and Pi-hole v6+.

## Commands

```sh
swift build                                   # compile
swift test                                    # API client tests (Swift Testing, URLProtocol stubs)
./scripts/build-app.sh                        # dist/Loophole.app, ad-hoc signed
./scripts/build-app.sh --install              # …and copy to /Applications and launch
swift run Loophole --demo                     # the real menu bar app with sample data, no Pi-hole
swift run Loophole --demo --paused            # same, mid-pause (countdown in the menu bar)
swift run Loophole --snapshot <dir>           # PNGs of every state, for design review and the README
swift run Loophole --demo --capture-popover <dir>   # open the real panel and capture it
swift scripts/make-icon.swift                 # regenerate Support/AppIcon.icns
./scripts/release.sh                          # signed, notarized dist/Loophole-<version>.dmg
```

The `--demo`, `--snapshot` and `--capture-popover` flags exist only in debug builds (`#if DEBUG` in `Snapshot.swift`).

## Pi-hole API

All calls are in `PiholeClient`. The API spec lives in the Pi-hole FTL repository (`src/api/docs/content/specs/*.yaml`); the public docs site covers authentication but not most endpoints.

| Call | Use |
| --- | --- |
| `POST /api/auth` `{password}` | Returns `session.sid`; sent afterwards as the `X-FTL-SID` header |
| `DELETE /api/auth` | Log out on quit or when settings change, to free the session seat |
| `GET /api/dns/blocking` | `blocking` is `"enabled"`/`"disabled"` (the docs also show a boolean; both are decoded), `timer` is seconds left or null |
| `POST /api/dns/blocking` `{blocking, timer}` | Switch; `timer: null` means indefinitely |
| `GET /api/stats/summary` | `queries.total`, `.blocked`, `.percent_blocked`, `.frequency` (per second; shown per minute), `gravity.domains_being_blocked` |
| `GET /api/info/system` | `system.cpu.load.raw` (three load averages), `system.memory.ram["%used"]` |

Behaviour worth knowing:

- Sessions expire. On a 401 the client logs in again and retries once. With no password configured it skips login entirely.
- A login that returns `valid: false` with `totp: true` is reported as "use an app password".
- The summary covers Pi-hole's in-memory history, which is the last 24 hours by default (`webserver.api.maxHistory`); it is not "since boot". The Domains on Lists tile is a current count, not a 24-hour figure.
- Status is polled every 30 seconds; stats and system info load when the panel opens.
- Switching is optimistic: the UI changes immediately and is corrected by the server's answer.

## Design decisions and their reasons

**Custom status item and panel, not `MenuBarExtra`.** SwiftUI's `MenuBarExtra(.window)` always draws a solid backdrop behind its content, and neither `containerBackground(.clear, for: .window)` nor `presentationBackground(.clear)` removes it. A Liquid Glass panel therefore needs its own transparent `NSPanel`. Consequences handled in `StatusItemController`: positioning under the item, closing on outside click / Esc / loss of key status, keeping the top-left corner fixed as content resizes, and a transparent margin so the glass's shadow is not clipped. The window's own shadow is off because it would be a hard rectangle.

**AppKit lifecycle.** Because the panel content is hosted in an `NSHostingController` outside any SwiftUI scene, `openWindow` is unavailable, so Settings is a plain `NSWindow`. Without SwiftUI's `App`, there is no automatic main menu; `AppDelegate` builds a minimal one so ⌘X/⌘C/⌘V/⌘A work in the Settings text fields.

**Liquid Glass with fallbacks.** `glassSurface`, `glassPanel`, `glassButtonStyle` and `GlassGroup` use the macOS 26 APIs when available and flat fills / classic button styles otherwise. The rest of the UI never checks the OS version. The macOS 15 fallback compiles but has not been run on a macOS 15 machine.

**Icons are drawn in code.** The mark is a shield with a hole punched through it. `MenuBarIcon` draws it as a template image: whole shield = blocking on, punched shield = off or paused, dimmed = no connection. Template images carry only opacity, so the two-tone look comes from two alpha strengths (left face 100%, right face 62%). `scripts/make-icon.swift` draws the same path for the app icon; the path is duplicated there because a script cannot import the app module. Do not use SF Symbols for the app icon — their licence does not allow it — and do not use the Pi-hole logo, which is a trademark.

**Global shortcuts use Carbon** (`RegisterEventHotKey`), which needs no accessibility permission and no third-party package.

**No dependencies.** A package that ships its own resource bundle would also complicate the hand-assembled app bundle and its code signature.

## Product decisions already made

These were tried or considered and deliberately dropped; do not reintroduce them without being asked.

- A "recently blocked" list with one-click allow, and an "allow or block a domain" field: built, then removed. The app no longer reads the query log or writes to allow/deny lists.
- A coloured pill around the menu bar countdown: built, then reverted to plain text.
- Dimming alone as the menu bar's on/off signal: replaced by distinct shapes.
- Pi-hole v5 support: not implemented; v6 only.

The look to aim for is an Apple first-party menu bar panel: system controls, restrained colour, sentence-case labels, Title Case section headers.

## Verifying UI changes

Liquid Glass and focused control colours exist only in the window server's composited output, so offscreen rendering (`cacheDisplay`, `ImageRenderer`) shows neither. `Snapshot.swift` therefore shows real windows briefly and captures them with `screencapture -l <windowNumber>`.

- `--snapshot <dir>` renders the panel in five states × light/dark over a built-in gradient "wallpaper", plus Settings and an enlarged sheet of the menu bar glyphs. These are the README images; copy the chosen ones into `docs/`.
- `--demo --capture-popover <dir>` clicks the real status item and captures the panel as it appears on screen (`on-screen.png` includes whatever is behind it — check before sharing), plus the menu bar item itself.
- A window-only capture cannot show what the glass refracts; use the on-screen capture to judge translucency.
- The status item can land in the menu bar's overflow area on a crowded bar, in which case live captures miss it.

After a UI change, look at the snapshots before reporting it done.

## Settings and storage

- `UserDefaults`: `address`, `allowSelfSigned`, `showCountdown`, `shortcutPauseMinutes`, `customAmount`, `customUnit`, `shortcut.pause`, `shortcut.resume`.
- The password is a generic password in the login keychain under the bundle identifier. Ad-hoc signed builds get a new signature on every rebuild, so macOS may ask for keychain access again; Developer ID builds do not have this problem.
- The bundle identifier is in `Support/Info.plist` and repeated in `Keychain.swift`. Changing it resets users' settings and saved password.
- `Info.plist` allows arbitrary loads (Pi-hole is usually plain HTTP on a user-chosen host) and declares local-network use. The self-signed option trusts only the configured host.

## Releasing

`scripts/release.sh` builds a universal app (arm64 + x86_64), signs it with a Developer ID Application certificate and the hardened runtime, notarizes and staples the app, packages a drag-to-Applications DMG, then signs, notarizes and staples that. It needs:

- a "Developer ID Application" certificate in the keychain (auto-detected, or set `SIGN_IDENTITY`);
- notary credentials: a keychain profile named `loophole-notary` (`xcrun notarytool store-credentials`, run in a real terminal because it prompts), or `NOTARY_KEY` / `NOTARY_KEY_ID` / `NOTARY_ISSUER` for an App Store Connect API key.

`--skip-notarize` exercises the packaging without contacting Apple. `VERSION` overrides the version in `Info.plist`.

`.github/workflows/release.yml` runs the same script when a `v*` tag is pushed and attaches the DMG to the release. It does nothing until the signing secrets listed at the top of the file are configured, and it has not yet been exercised end to end. Releases so far were built locally and published with `gh release create`.

Known noise: the universal build warns that x86_64 is deprecated; that is expected.

## Conventions

- Swift 6 language mode; UI types are `@MainActor`, the API client is an actor.
- Comments explain why, not what. Keep them when they still apply.
- Tests cover the API client only, through `URLProtocol` stubs. UI is verified with snapshots.
- User-facing errors are plain sentences (`PiholeError.errorDescription`).
- Keep personal details (names, emails, team identifiers, home paths, network addresses) out of the repository, including documentation and screenshots. Screenshots use sample data.
